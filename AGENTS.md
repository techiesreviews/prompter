# techies-prompter

Public teleprompter at https://prompter.techies.tools plus an open, stateless MCP endpoint at `/mcp`. Owner: Lex (non-technical; explain in plain words).

## Rules

- Agent Kit (the shared kit, `scripts/agents/kit`) for all coding: `kit doctor` first, `kit unit` on every change, `kit specs` (browser checks) and `kit size` for page changes. This project's notes on the kit (its commands, release steps): `docs/agents/kitchen-extras.md`. Delegated work must carry this requirement.
- Scripts stay on the user's device. Never add server-side storage (KV, D1, R2, Durable Object storage, Cache API for scripts) or logging of request bodies. Keep `observability` off. Scripts travel in the URL fragment `#s=`; the only other way is the user's own agent through the live relay below, in memory only.
- Two exceptions, both Durable Objects that keep no script and log nothing:
  - The `/mcp` rate limiter in `src/limiter.mjs`: one object per hashed client (salted SHA-256 of the IP, never the raw IP) that counts requests in memory only. It must never use `ctx.storage`, receive a request body, or log.
  - The live relay in `src/relay.mjs` (approved by Lex, 2026-10-28), as in the script editor: one object per hashed agent token (`src/token.mjs`; salted SHA-256, never the token). Its storage holds only the note `{ createdAt, expiresAt, revoked, agent: { name, version } }`, which an alarm just after `expiresAt` (8 hours after the token's birth) erases; never script text. Scripts sent by the user's own agent (`show_script`), the open script the agent reads (`get_open_script`) and the Producer's suggestions (`push_suggestions`, `clear_suggestions`) pass through it in memory only and are never stored or logged. Disconnect MCP marks the note revoked, so the token gets 401 until the alarm erases it.
  - Only `/mcp` may call the limiter. Only `/mcp` and `/api/*` (`/api/agent-token`, `/api/relay`, each with an in-memory per-client guard) touch the relay. Every route asks the same checks from `src/guard.mjs` (the client key, grouped as the limiter groups it; the other-website check, which open `/mcp` without a token skips on purpose so any website's MCP client works; the limits) and the agent's name and version are cleaned there; `test/guard.test.mjs` tries each route.
- Cloudflare free plan only. No paid features.
- `src/core.mjs` is the single source of truth for the format, presets ("lex" and "default"), checker, camera cues (`faceCue`), link encoding and the demo script. The page inlines it (and `src/settings.mjs`, the settings table: each setting's storage key, default and limits or choices, which reading at start-up and saving both use, plus the other keys the page keeps on the device; the live site's keys must never change, `test/settings.test.mjs` checks they stay and that no other file types a key or a default by hand, `src/follow.mjs`, the voice-follow line matching, `src/open-script.mjs`, the open script's own state, made fresh on each open so nothing carries over from the script before, `src/speech.mjs`, the speech recognition keeper, `src/agent.mjs`, the Wait for MCP / Copy MCP messages and the agent's shown name, `src/wire.mjs`, the live relay's wire list (subprotocol, close codes, paths, message types and their fields; the Worker and the relay read it too), `src/relay-link.mjs`, the tab's live relay link (token, socket, backoff, keepalive, tool calls), `src/suggestions.mjs`, the Producer's cue queue and the check of what the agent pushes (the Worker's `/mcp` uses it too), `src/camframe.mjs`, the CamFrame link client, `src/reading-line.mjs`, what is at the reading line (one look per animation frame) and bringing a line to it, and `src/ui/range-field.mjs` with its `src/ui/range-field.css`, the reusable slider) at build time, so all twelve scripts must stay import-free (except a named import from one inlined before it, such as `src/relay-link.mjs` from `src/wire.mjs` and `src/settings.mjs`, which the build drops) and use only `export function`/`export const` forms.
- Follow my voice uses the browser's own speech recognition (Web Speech API) and is opt-in after a notice that the browser sends audio to its speech service. The page itself never sends audio anywhere, and sends the script only to the user's own connected agent when it asks (`get_open_script`). The page's `Permissions-Policy` allows the microphone for this origin only. Speech recognition is kept running by `speechKeeper` in `src/speech.mjs` (Lex, 2026-10-30: it kept disconnecting in Edge and Chrome): every start is a fresh recognition object (the old one cut loose and aborted, so never two at once and never an ended one started again); a session that ends (Chrome after about a minute, an Edge `network` drop, any passing error) starts again at once, and only quick failures in a row wait a little (0.25 to at most 2 s); a watchdog replaces a session that has gone quiet (no result for 10 s, or 5 s while it hears sound: the silent stall); "Reconnecting to speech…" shows by the reading line (read out once) only after two quick failures in a row and goes when words are heard. Passing errors never turn it off; a blocked microphone and the like do, a recognizer that cannot be made or started before any word was heard ("could not start in this browser") does at once (after words, it is a passing failure; a start refused as not allowed turns it off like a blocked microphone), and so does a browser that heard no word since it was turned on and kept failing for 15 s (the message names browsers without a speech service). Where the browser recognises speech on this device (`SpeechRecognition.available`/`install` with `processLocally`, Chrome 139 and later; feature-detected, absent in Edge) it is used, installing the language pack from the turn-on click, because it needs no network; a missing pack falls back to the browser's service silently. The default Permissions-Policy allowlist for `on-device-speech-recognition` is `self`, so the page's header needs no change. No second microphone stream (no audio level meter): restarting a quiet session costs nothing.
- Design: the kit's house style (`docs/house-style.md` in the folder `scripts/agents/kit --home` prints), plus: the Techies Reviews dark palette (indigo night page, bright orange actions), Inter and Roboto Mono. The plain address shows a start screen (never opens a script by itself; its Continue button also says when that script was saved, when known: from the link's `&d=YYYY-MM-DD`, an opened file's own date, or the agent's `saved`, never guessed, and no date for a pasted script); a script reads left-aligned in a centred column. No sidebar: one floating control bar (Open, previous, play, next, clock, Settings) with Open and Settings popovers (native Popover API, CSS anchor positioning with a script fallback). Open holds the agent block (Wait for MCP, as in the script editor), shown on its button only as a small status dot. Settings: text size and scroll speed (the shared range field, `src/ui/README.md`), width, line spacing (Normal, the default and the old look, Roomy or Spacious: taller lines, also inside a wrapped line, and more room between script lines; remembered per device; the row at the reading line stays put when it changes; only while Follow my voice's own move is in progress (until its scroll ends, the reader's wheel or touch, or 2 seconds if the browser never says so), the line being read goes to the reading line), then three big icon buttons side by side, about as tall as the control bar: Follow my voice (microphone; only with the speech API, otherwise the other two share the row), Main screen (monitor; Connect / Reconnect) and the CamFrame link (camera; `aria-pressed`, turns the remembered setting on and off), icons only (names for screen readers and a hover title), a quiet outline icon when off and orange and filled when on. CamFrame's button also shows the link's state, with no status text on screen (Lex, 2026-10-30; the paste window's Camera cues list is the one place for the layouts' state, Lex 2026-11-06, see `docs/camframe/layouts.md`): looking or reconnecting a blinking orange outline camera (reduced motion: a dashed orange ring, no blinking), connected a filled orange camera with a steady glow, not found a quiet crossed-out camera with a thin orange ring; its name and title say the state in words ("CamFrame link: connected"), not found adds the Open CamFrame / Chrome permission help to the title, and connected (not again after reconnecting) and not found are read out once through the status line. A dot on Settings while voice is on, a main screen is connected or CamFrame is connected. While Follow my voice is on, the line being read is pure white (`--text-now`) and the lines after it in its section dimmer (`--upcoming`, still AA), with no box or underline; `src/follow.mjs` moves it word by word and line by line, never on a single word or a pair of common words from a later line. No status messages on screen (except the short Reconnecting to speech note by the reading line, the Producer's cue pill and box, the start screen's "Couldn’t save “<its name, as Continue would show it>” on this device" ("your latest …" when Continue shows the same name) just under Continue, only when the browser could not keep the last script opened (Lex, 2026-11-15, TOOLS-272), in the paste window the one line where the Camera cues list is when CamFrame is not connected and the one line where the two camera layouts stand in CamFrame): the status line is for screen readers only; copy feedback lives on the button itself. Text colours must meet WCAG AA (4.5:1) on their backgrounds; white on orange only at 19px bold (large text). `test/contrast.test.mjs` checks every text colour, the page's tokens and each shared component's in `src/ui/`.
- The Producer's cues (Lex chose the v3 look of the TOOLS-464 prototype, 2026-11-25; it replaces the TOOLS-347 strip): while the user's agent is connected to both their Producer and this tab, `push_suggestions` sends 1 to 3 items `{ kind, text, number? }` (kinds in `SUGGESTION_KINDS`: question, next, steer, point, audience). At most `SUGGESTIONS_WAITING` (3) wait, the newest on top; a newer one pushes the oldest off. With a script open they show as one small cue pill at the end of the reading line ("? Question", "★ Talking point", "@ Audience", "↩ Steer back", plus "+N" when more wait), filled in the kind's colour; it never changes the script's layout. A tap or Enter opens the newest in a box centred over the dimmed script (a veil below the control bar), in big type with no label, with dots for how many wait. No border, coloured edge band or ring on the pill or the box, and no 1px highlight in their shadow (Lex, 2026-11-25: never; the browser test checks it). No on-screen arrows. Keys while the box is open: ← → and Page Up/Down (a clicker) move between the cues, ↑ ↓ scroll a long one, Enter is Use, Esc is Skip; a tap beside closes it and the cue waits behind the pill again. A new push never moves the box off the cue being read. Auto-scroll and Follow my voice wait while the box is open and go on after. Play keeps showing whether auto-scroll is on while the box shows (the box only makes the scrolling wait): a click turns it off or on, and its tip says what happens when the cue closes; Space on a focused control bar button does the same, as it means auto-scroll there without the box too (elsewhere Space waits while the box shows). Words heard while the box shows, also the rest of a phrase begun then, are never followed: the phrase has ended only once the speech service has finished every result and a second (`VOICE_PAUSE_MS`) passes with no result, so a result that comes late, however long after the one before, is no pause; a new speech session takes a phrase the old one left unfinished as still spoken (`voiceHeld`/`voiceUnheld`/`voiceHoldSession` in `src/follow.mjs`). With no script open (a live show) the box shows by itself; a tap beside sets the cues aside behind the pill in the top corner (clear of the start card) until it is tapped or a new cue comes, and a tap beside with a script open sets them aside the same way. The main-screen hint never shows over the box. Use marks a cue used (a used prepared question's number goes to the Producer as Asked), Skip passes it; the agent's next `push_suggestions` or `clear_suggestions` returns them once (`used`, `skipped`, `asked`). The cues show only while the agent is connected here and its pushes keep coming (`SUGGESTION_STALE_MS`, 2 minutes), so they are never a dead control; Disconnect MCP clears them. Talking points come only from the show plan or from what was said (the tool's description says so). Nothing is stored.
- One click from the Producer (TOOLS-464, option a): `/api/agent-token` answers CORS (its `OPTIONS` and its `POST`) for the Producer's exact addresses in `PRODUCER_ORIGINS` (`src/wire.mjs`) only, never a wildcard, so the Producer page can read a new token. It then opens this page with `#producer` (never a token in the address: a sent link must not link anyone's tab to someone else's agent); the page takes the hash off the address at once (`history.replaceState`), posts `PRODUCER_MESSAGES.ready` to `window.opener` at each `PRODUCER_ORIGINS` address, and takes the token once, only from a `PRODUCER_MESSAGES.token` message whose origin is in `PRODUCER_ORIGINS` and whose source is that opener; the tab says ready once, at load, and the Producer may answer any time after (for example once its token request finishes); until then it tells the opener nothing; then it connects as Wait for MCP would (a token it had before, also an old Producer link, is revoked quietly: never "off" in between, TOOLS-476), and the Open button's name adds "linked to your Producer". The tab tells the opener its link state only (`PRODUCER_MESSAGES.link`, never the token), by `postMessage` to each `PRODUCER_ORIGINS` address (never `"*"`), and hears only `PRODUCER_MESSAGES.disconnect` from that opener at those addresses (Disconnect both). The Producer must POST for the token with no body (the preflight allows no extra headers) and must not cut the opener link (no `noopener`, no COOP). `test/wire.test.mjs` and the browser specs check this.
- The reading line can be dragged to camera height (remembered per device), and text above it is deliberately faded below WCAG AA (`--read-veil`) because it has been read. This is the one deliberate exception to the AA rule; do not raise it. `test/contrast.test.mjs` checks that it stays low.
- CamFrame link (approved by Lex, 2026-10-30): off by default (CamFrame's button in Settings, remembered per device). When on, the page calls only `http://127.0.0.1:47833` (CamFrame on the user's own computer): `GET /camframe/status`, and `POST /camframe/cue` with just the cue `{ size, position?, scene? }` when a `[Face …]` cue line reaches the reading line, once per pass down (re-armed when scrolled back above; a jump past several cues sends only the last; nothing until the person first touches the page after it loads, so a reload the browser scrolls back sends nothing). Never the script. Camera layouts (Lex, 2026-11-04): with a CamFrame that answers `"api": 2`, the page may also `POST /camframe/scenes` with the two layout Scenes "Live small corner" and "Live right large" (missing ones by itself when CamFrame connects, unless that would leave no spare slot or no room: then nothing is saved and the Camera cues list says so; never `replace` (no button for it since 2026-11-06), never `apply`, never `/camframe/small-size`); details in `docs/camframe/layouts.md`. Failures change CamFrame's button in Settings and never block scrolling. Calls to this computer fail now and then (Edge especially), so the link is steady (`camframeAfterCheck` in `src/camframe.mjs`): one or two missed status checks in a row after it was connected say Reconnecting (a first look that misses keeps Looking) and check again after 1 and 2 s (while the page is in view); only three in a row say not found (then the usual 10 s checks reconnect by themselves when CamFrame answers); each call waits up to 3 s; a cue that does not get through is sent once more after 0.4 s (not when a newer cue or another script came first), and only then counts as a miss; a cue still on its way when the link is turned off (and on again) changes nothing. A cue line always reads as an instruction (a camera mark, "Camera: face small" bold in the line colour, its other words muted), link on or off. No note pops up when a cue is sent, refused or not reached (Lex, 2026-10-30: the camera moving is the sign it worked).
- The built page must stay one self-contained HTML file that works offline (no external scripts, styles or fetches). Its only calls go to its own site for the live connection (`/api/agent-token` and the `/api/relay` WebSocket) and, once the user turns the CamFrame link on, to CamFrame on `127.0.0.1:47833` (CSP `connect-src 'self' wss://prompter.techies.tools http://127.0.0.1:47833 ws://127.0.0.1:4455 ws://localhost:4455`; the preview's build names its own address, `scripts/build.mjs --host`). The CSP also lets the page reach OBS's WebSocket on the user's own computer (`ws://127.0.0.1:4455` and `ws://localhost:4455`, OBS's default port; Lex, 2026-11-14), so a later OBS link is not refused; the page itself makes no OBS call yet, and no other address may be added without a wildcard-free test in `test/build.test.mjs`; a file:// copy has no relay and its Copy MCP copies the open server's message. The only extra files are the two fonts in `fonts/` (SIL OFL 1.1, licence in `fonts/OFL.txt`), served from `/fonts/` (CSP `font-src 'self'`); the page adds their `@font-face` only when served over http(s), so a file:// copy uses system fonts.
- CSS: simple, low-specificity, shared helpers first; bounded component overrides with `@scope` only where losing them is harmless. Respect `prefers-reduced-motion`. Keep mobile usable.
- Do not deploy, push or change Cloudflare resources unless the lead says so.
