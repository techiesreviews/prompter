# techies-prompter

Public teleprompter at https://prompter.techies.tools plus an open, stateless MCP endpoint at `/mcp`. Owner: Lex (non-technical; explain in plain words).

## Rules

- Agent Kit (the shared kit, `scripts/agents/kit`) for all coding: `kit doctor` first, `kit unit` on every change, `kit specs` (browser checks) and `kit size` for page changes. This project's notes on the kit (its commands, release steps): `docs/agents/kitchen-extras.md`. Delegated work must carry this requirement.
- Scripts stay on the user's device. Never add server-side storage (KV, D1, R2, Durable Object storage, Cache API for scripts) or logging of request bodies. Keep `observability` off. Scripts travel in the URL fragment `#s=`; the only other way is the user's own agent through the live relay below, in memory only.
- Two exceptions, both Durable Objects that keep no script and log nothing:
  - The `/mcp` rate limiter in `src/limiter.mjs`: one object per hashed client (salted SHA-256 of the IP, never the raw IP) that counts requests in memory only. It must never use `ctx.storage`, receive a request body, or log.
  - The live relay in `src/relay.mjs` (approved by Lex, 2026-10-28), as in the script editor: one object per hashed agent token (`src/token.mjs`; salted SHA-256, never the token). Its storage holds only the note `{ createdAt, expiresAt, revoked, agent: { name, version } }`, which an alarm just after `expiresAt` (8 hours after the token's birth) erases; never script text. Scripts sent by the user's own agent (`show_script`), the open script the agent reads (`get_open_script`) and the Producer's suggestions (`push_suggestions`, `clear_suggestions`) pass through it in memory only and are never stored or logged. Disconnect MCP marks the note revoked, so the token gets 401 until the alarm erases it.
  - Only `/mcp` may call the limiter. Only `/mcp` and `/api/*` (`/api/agent-token`, `/api/relay`, each with an in-memory per-client guard) touch the relay. Every route asks the same checks from `src/guard.mjs` (the client key, grouped as the limiter groups it; the other-website check, which open `/mcp` without a token skips on purpose so any website's MCP client works; the limits) and the agent's name and version are cleaned there; `test/guard.test.mjs` tries each route.
- Cloudflare free plan only. No paid features.
- `src/core.mjs` is the single source of truth for the format, presets ("lex" and "default"), checker, camera cues (`faceCue`), link encoding and the demo script. The page inlines it (and `src/settings.mjs`, the settings table: each setting's storage key, default and limits or choices, which reading at start-up and saving both use, plus the other keys the page keeps on the device; the live site's keys must never change (a key leaves only through `RETIRED` in `src/settings.mjs`, with Lex's OK, as `prompter-spacing` did in TOOLS-486; the page then clears it from the device at start-up), `test/settings.test.mjs` checks they stay and that no other file types a key or a default by hand, `src/follow.mjs`, the voice-follow line matching, `src/open-script.mjs`, the open script's own state, made fresh on each open so nothing carries over from the script before, `src/speech.mjs`, the speech recognition keeper, `src/agent.mjs`, the Wait for MCP / Copy MCP messages and the agent's shown name, `src/wire.mjs`, the live relay's wire list (subprotocol, close codes, paths, message types and their fields; the Worker and the relay read it too), `src/relay-link.mjs`, the tab's live relay link (token, socket, backoff, keepalive, tool calls), `src/suggestions.mjs`, the Producer's cue queue and the check of what the agent pushes (the Worker's `/mcp` uses it too), `src/camframe.mjs`, the CamFrame link client, `src/obs.mjs`, the OBS link (obs-websocket v5) and the take names and take book, `src/reading-line.mjs`, what is at the reading line (one look per animation frame) and bringing a line to it, `src/next-up.mjs`, the Text only switches and the rows of the strip that shows them, `src/main-screen.mjs`, the main screen's rules (the sites that cut it off, which screen a new one opens on), and `src/ui/range-field.mjs` with its `src/ui/range-field.css`, the reusable slider) at build time, so all fifteen scripts must stay import-free (except a named import from one inlined before it, such as `src/relay-link.mjs` from `src/wire.mjs` and `src/settings.mjs`, which the build drops) and use only `export function`/`export const` forms.
- Follow my voice uses the browser's own speech recognition (Web Speech API) and is opt-in after a notice that the browser sends audio to its speech service. The page itself never sends audio anywhere, and sends the script only to the user's own connected agent when it asks (`get_open_script`). The page's `Permissions-Policy` allows the microphone for this origin only. Speech recognition is kept running by `speechKeeper` in `src/speech.mjs` (Lex, 2026-10-30: it kept disconnecting in Edge and Chrome): every start is a fresh recognition object (the old one cut loose and aborted, so never two at once and never an ended one started again); a session that ends (Chrome after about a minute, an Edge `network` drop, any passing error) starts again at once, and only quick failures in a row wait a little (0.25 to at most 2 s); a watchdog replaces a session that has gone quiet (no result for 10 s, or 5 s while it hears sound: the silent stall); "Reconnecting to speech…" shows by the reading line (low on the right above the control bar when the record light leaves no room above the line; read out once) only after two quick failures in a row and goes when words are heard. Passing errors never turn it off; a blocked microphone and the like do, a recognizer that cannot be made or started before any word was heard ("could not start in this browser") does at once (after words, it is a passing failure; a start refused as not allowed turns it off like a blocked microphone), and so does a browser that heard no word since it was turned on and kept failing for 15 s (the message names browsers without a speech service). Where the browser recognises speech on this device (`SpeechRecognition.available`/`install` with `processLocally`, Chrome 139 and later; feature-detected, absent in Edge) it is used, installing the language pack from the turn-on click, because it needs no network; a missing pack falls back to the browser's service silently. The default Permissions-Policy allowlist for `on-device-speech-recognition` is `self`, so the page's header needs no change. No second microphone stream (no audio level meter): restarting a quiet session costs nothing.

- The Producer's cues (Lex chose the v3 look of the TOOLS-464 prototype, 2026-11-25; it replaces the TOOLS-347 strip): while the user's agent is connected to both their Producer and this tab, `push_suggestions` sends 1 to 3 items `{ kind, text, number? }` (kinds in `SUGGESTION_KINDS`: question, next, steer, point, audience). No border, coloured edge band or ring on the pill or the box, and no 1px highlight in their shadow (Lex, 2026-11-25: never; the browser test checks it). No on-screen arrows. Words heard while the box shows, also the rest of a phrase begun then, are never followed: the phrase has ended only once the speech service has finished every result and a second (`VOICE_PAUSE_MS`) passes with no result, so a result that comes late, however long after the one before, is no pause; a new speech session takes a phrase the old one left unfinished as still spoken (`voiceHeld`/`voiceUnheld`/`voiceHoldSession` in `src/follow.mjs`). The cues show only while the agent is connected here and its pushes keep coming (`SUGGESTION_STALE_MS`, 2 minutes), so they are never a dead control; Disconnect MCP clears them, and so does a new Producer link that replaces the old one (TOOLS-476).
