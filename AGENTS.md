# techies-prompter

Public teleprompter at https://prompter.techies.tools plus an open, stateless MCP endpoint at `/mcp`. Owner: Lex (non-technical; explain in plain words).

## Rules

- Agent Kit is required for all coding: read `docs/agents/agent-scripts.md`, run `scripts/agents/kit --help` and `kit doctor` first, then `kit specs` (and `kit shots`, `kit size` for page changes). Delegated work must carry this requirement.
- Scripts stay on the user's device. Never add server-side storage (KV, D1, R2, Durable Object storage, Cache API for scripts) or logging of request bodies. Keep `observability` off. Scripts travel in the URL fragment `#s=`; the only other way is the user's own agent through the live relay below, in memory only.
- Two exceptions, both Durable Objects that keep no script and log nothing:
  - The `/mcp` rate limiter in `src/limiter.mjs`: one object per hashed client (salted SHA-256 of the IP, never the raw IP) that counts requests in memory only. It must never use `ctx.storage`, receive a request body, or log.
  - The live relay in `src/relay.mjs` (approved by Lex, 2026-10-28), as in the script editor: one object per hashed agent token (`src/token.mjs`; salted SHA-256, never the token). Its storage holds only the note `{ createdAt, expiresAt, revoked, agent: { name, version } }`, which an alarm just after `expiresAt` (8 hours after the token's birth) erases; never script text. Scripts sent by the user's own agent (`show_script`) and the open script the agent reads (`get_open_script`) pass through it in memory only and are never stored or logged. Disconnect MCP marks the note revoked, so the token gets 401 until the alarm erases it.
  - Only `/mcp` may call the limiter. Only `/mcp` and `/api/*` (`/api/agent-token`, `/api/relay`, each with an in-memory per-client guard) touch the relay.
- Cloudflare free plan only. No paid features.
- `src/core.mjs` is the single source of truth for the format, presets ("lex" and "default"), checker, camera cues (`faceCue`), link encoding and the demo script. The page inlines it (and `src/follow.mjs`, the voice-follow line matching, `src/speech.mjs`, the speech recognition keeper, `src/agent.mjs`, the Wait for MCP / Copy MCP messages and the agent's shown name, `src/camframe.mjs`, the CamFrame link client, and `src/ui/range-field.mjs` with its `src/ui/range-field.css`, the reusable slider) at build time, so all six scripts must stay import-free and use only `export function`/`export const` forms.
- Follow my voice uses the browser's own speech recognition (Web Speech API) and is opt-in after a notice that the browser sends audio to its speech service. The page itself never sends audio anywhere, and sends the script only to the user's own connected agent when it asks (`get_open_script`). The page's `Permissions-Policy` allows the microphone for this origin only. Speech recognition is kept running by `speechKeeper` in `src/speech.mjs` (Lex, 2026-10-30: it kept disconnecting in Edge and Chrome): every start is a fresh recognition object (the old one cut loose and aborted, so never two at once and never an ended one started again); a session that ends (Chrome after about a minute, an Edge `network` drop, any passing error) starts again at once, and only quick failures in a row wait a little (0.25 to at most 2 s); a watchdog replaces a session that has gone quiet (no result for 10 s, or 5 s while it hears sound: the silent stall); "Reconnecting to speech…" shows by the reading line (read out once) only after two quick failures in a row and goes when words are heard. Passing errors never turn it off; a blocked microphone and the like do, a recognizer that cannot be made or started before any word was heard ("could not start in this browser") does at once (after words, it is a passing failure), and so does a browser that heard no word since it was turned on and kept failing for 15 s (the message names browsers without a speech service). Where the browser recognises speech on this device (`SpeechRecognition.available`/`install` with `processLocally`, Chrome 139 and later; feature-detected, absent in Edge) it is used, installing the language pack from the turn-on click, because it needs no network; a missing pack falls back to the browser's service silently. The default Permissions-Policy allowlist for `on-device-speech-recognition` is `self`, so the page's header needs no change. No second microphone stream (no audio level meter): restarting a quiet session costs nothing.
- Design: the Techies Reviews dark palette (indigo night page, bright orange actions), Inter and Roboto Mono. The plain address shows a start screen (never opens a script by itself); a script reads left-aligned in a centred column. No sidebar: one floating control bar (Open, previous, play, next, clock, Settings) with Open and Settings popovers (native Popover API, CSS anchor positioning with a script fallback). The Open popover holds the agent block (Wait for MCP, as in the script editor); the Open button shows only a small status dot for it. Settings: text size and scroll speed (range fields, `src/ui/`: one 44px box that is all slider: an indigo fill from the very start to the very end, under the name and the value, with a white grip at its end (faint at rest, bright on hover, while dragging and when focused), faint ticks, and the value on the right that can be typed exactly, also past the slider's ends), width, then three big icon buttons side by side, about as tall as the control bar: Follow my voice (microphone; only with the speech API, otherwise the other two share the row), Main screen (monitor; Connect / Reconnect) and the CamFrame link (camera; `aria-pressed`, turns the remembered setting on and off), icons only (names for screen readers and a hover title), on the same quiet indigo button: the icon is a quiet outline when off and orange and filled when on. CamFrame's button also shows the link's state, with no status text on screen (Lex, 2026-10-30): looking or reconnecting a blinking orange outline camera (reduced motion: a dashed orange ring, no blinking), connected a filled orange camera with a steady glow, not found a quiet crossed-out camera with a thin orange ring; its name and title say the state in words ("CamFrame link: connected"), not found adds the Open CamFrame / Chrome permission help to the title, and connected (not again after reconnecting) and not found are read out once through the status line; the Settings button shows a small dot while voice is on, a main screen is connected or CamFrame is connected. While Follow my voice is on, the line being read is pure white (`--text-now`) and the lines after it in its section a little dimmer (`--upcoming`, still AA), with no box or underline; it follows word by word and line by line (`src/follow.mjs`): a single word or a pair of common words from a later line never moves it. No status messages appear on screen (except the short Reconnecting to speech note by the reading line): the page's status line is for screen readers only (visually hidden). Copy feedback (Wait for MCP, Copy link) lives on the button itself (label and check); Copy link's spoken confirmation goes through the hidden status line. Text colours must meet WCAG AA (4.5:1) on their backgrounds; white on orange only at 19px bold (large text). `test/contrast.test.mjs` checks the `oklch()` tokens in `src/page.html`.
- The reading line can be dragged to camera height (remembered per device), and text above it is deliberately faded below WCAG AA (`--read-veil`) because it has been read. This is the one deliberate exception to the AA rule; do not raise it. `test/contrast.test.mjs` checks that it stays low.
- CamFrame link (approved by Lex, 2026-10-30): off by default (CamFrame's button in Settings, remembered per device). When on, the page calls only `http://127.0.0.1:47833` (CamFrame on the user's own computer): `GET /camframe/status`, and `POST /camframe/cue` with just the cue `{ size, position?, scene? }` when a `[Face …]` cue line reaches the reading line, once per pass down (re-armed when scrolled back above; a jump past several cues sends only the last; nothing until the person first touches the page after it loads, so a reload the browser scrolls back sends nothing). Never the script. Failures change CamFrame's button in Settings and never block scrolling. Calls to this computer fail now and then (Edge especially), so the link is steady (`camframeAfterCheck` in `src/camframe.mjs`): one or two missed status checks in a row after it was connected say Reconnecting (a first look that misses keeps Looking) and check again after 1 and 2 s (while the page is in view); only three in a row say not found (then the usual 10 s checks reconnect by themselves when CamFrame answers); each call waits up to 3 s; a cue that does not get through is sent once more after 0.4 s, and only then counts as a miss; a cue still on its way when the link is turned off (and on again) changes nothing. A cue line always reads as an instruction (a camera mark, "Camera: face small" bold in the line colour, its other words muted), link on or off. No note pops up when a cue is sent, refused or not reached (Lex, 2026-10-30: the camera moving is the sign it worked).
- The built page must stay one self-contained HTML file that works offline (no external scripts, styles or fetches). Its only calls go to its own site for the live connection (`/api/agent-token` and the `/api/relay` WebSocket) and, once the user turns the CamFrame link on, to CamFrame on `127.0.0.1:47833` (CSP `connect-src 'self' wss://prompter.techies.tools http://127.0.0.1:47833`); a file:// copy has no relay and its Copy MCP copies the open server's message. The only extra files are the two fonts in `fonts/` (SIL OFL 1.1, licence in `fonts/OFL.txt`), served from `/fonts/` (CSP `font-src 'self'`); the page adds their `@font-face` only when served over http(s), so a file:// copy uses system fonts.
- CSS: simple, low-specificity, shared helpers first; bounded component overrides with `@scope` only where losing them is harmless. Respect `prefers-reduced-motion`. Keep mobile usable.
- Review with `kit review` (Claude only). Do not run GPT/Codex reviews.
- Do not deploy, push or change Cloudflare resources unless the lead says so.
